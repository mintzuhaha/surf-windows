# Decisions

One or two lines per choice, with the why. Newest at the bottom.

- **2026-10-27 · Backend service, not a Chrome extension.** It has to keep working when the laptop is closed, and the calendar on my phone is the real interface.
- **2026-10-27 · Calendar feed (ICS) before the Google Calendar API.** No sign-in needed, so it ships today. Tradeoff: Google refreshes subscribed calendars on its own schedule, often hours apart. Revisit in M1.
- **2026-10-27 · Wave-height buckets instead of board profiles.** Simpler to configure, and it's how surfers actually describe conditions.
- **2026-10-27 · Three-state preferences (skip / will surf / favored).** One control gives both a filter and a ranking.
- **2026-10-27 · Hourly granularity.** Matches the forecast data. Windows are whole hours.
- **2026-10-27 · Stateless, no database.** Preferences live in config.yaml for now and will move into the feed URL in M3. Vercel's CDN cache stands in for storing forecasts.
- **2026-10-27 · Rough face-height conversion.** Open-ocean swell height isn't what breaks at a sheltered spot, so the model applies a period factor and a spot factor. Both are guesses until calibrated against real sessions.
- **2026-10-27 · Swell at the spot's own coordinates.** Checked Open-Meteo Marine at 36.95469, -121.97253: it snaps to a sea cell (36.958, -121.958) with no nulls across all 168 hours, so no offshore point is needed. `record_fixtures.py` prints null counts to re-check.
- **2026-10-27 · Tides from Monterey (9413450), not Santa Cruz (9413745).** Santa Cruz is a subordinate station: NOAA serves only high/low there and rejects `interval=h`. Its published offsets from Monterey are 6-11 min and x0.97-0.99 height, too small to change a tide third or direction at hourly resolution, and this avoids interpolating highs/lows.
- **2026-10-27 · Faces below the smallest bucket are `flat`, always skip.** Config buckets start at 1 ft; anything smaller isn't worth a window. Hours with no wave data at all are `unknown` and also skip.
- **2026-10-27 · Near misses: best hour per (day, reason).** Ranked by how many of size/wind/tide are favored, then soonest; keeping one per day and reason stops one windy morning from filling all five slots. Shown in time order.
- **2026-10-27 · Events are TRANSPARENT, tentative ones STATUS:TENTATIVE.** A surf window is a suggestion, so it shouldn't mark you busy to people booking meetings.
- **2026-10-27 · Window size/wind/tide labels are the most common value across its hours.** Face and wind ranges show the spread; the swell detail comes from the window's biggest hour.
- **2026-10-27 · "Updated N minutes ago" is computed in the browser.** The CDN can serve a cached page for up to 90 minutes (s-maxage + stale-while-revalidate), so server-rendered relative time would be wrong; the page embeds the fetch timestamp and a few lines of JS format it.
- **2026-10-27 · Week grid scrolls inside its card on phones.** Seven day columns can't fit 390px legibly; the window cards below carry the same information and stack normally.
- **2026-10-27 · `api/index.py` routes `/feed.ics` itself.** Vercel builds this repo as one Python app with `api/index.py` as the entrypoint, so every path reached it and `/feed.ics` returned HTML. The entrypoint now dispatches by path (shared code in `api/_http.py`), and unknown paths return 404 so stray URLs like `/favicon.ico` don't trigger three API fetches.
- **2026-10-27 · Free hours default to all day.** Which hours to exclude is the user's call, so the default shows every good daylight period; `free_hours` stays in config to narrow it.
- **2026-10-27 · `size_factor` 0.6 -> 1.1.** Fitted to Surfline for Oct 28 noon/4pm (2-3 ft+) and Oct 30 8am/1pm/4pm (3-4 ft+): 0.6 gave 1.6-1.9 ft, 1.1 gives 2.9-3.5 ft. No single factor fits both days because Open-Meteo lacks the SSW groundswell on Oct 28 and we size from the primary swell only; direction-aware sizing is the real fix. Refine as more comparisons come in.
- **2026-10-27 · 15-minute dawn grace.** Civil dawn falls at 7:01-7:03am this week, so the strict rule dropped every 7-8am hour by a minute or two.
- **2026-10-27 · "High tide" is a per-break height, not the top third of the day.** Pleasure Point is surfable below 4.2 ft (`spot.high_tide_ft`). The old relative rule moved with each day's range: on Nov 1 the lows fall at night, so 3.3 ft counted as high and the whole day was skipped. Low vs mid stays relative to the day's range.
- **2026-10-27 · Tide thresholds apply to the whole hour.** An hour is `high` if the tide reaches 4.2 ft at its start or end, and ideal only if it stays under 3.7 ft at both. Judging by the start alone passed Thu 9-10am at 4.19 ft while it rose well past 4.2.
- **2026-10-27 · Ideal tide is per break (`spot.ideal_tide_ft`, 3.7 ft at Pleasure Point).** It upgrades the tide state to fav, so a chest-high hour at ideal tide is favored even when the wind is only light. Window cards and the feed now show each factor's state as the most common across the window's hours.
- **2026-10-27 · Picking windows is a skip list in the feed URL.** Google can't add several events from one link without the Calendar API (out of scope), so unchecked windows go in `feed.ics?skip=...` and the subscription keeps updating, with new windows still arriving. Tradeoffs: changing picks means subscribing to a new URL, and a skipped window comes back if its start hour shifts (its id changes).
- **2026-10-27 · Surf height on Surfline's scale, from every swell partition.** Fitted to 59 Surfline forecasts for Oct 28-Nov 4 (3-hourly, from screenshots; not committed): energy sum of primary swell, secondary swell and wind waves, each `height_ft × (period/10)^0.8`, west/NW swells (>= 245°, threshold set by hand) × 0.8, gain `size_factor` 1.4. Leave-one-day-out error 0.50 ft vs 0.73 ft for the old primary-swell model, which overstated short-period NW windswell by up to 2 ft. On the live forecast: Surfline's exact label for 20/43 hours, within one step for 41/43. Remaining misses come from Open-Meteo missing swells Surfline sees (e.g. the Oct 28 SSW groundswell).
- **2026-10-27 · Sizes display as Surfline-style ranges, and buckets use the same scale.** chest = 3-4 ft (Surfline: waist to shoulder), head = 4-5/4-6 ft, overhead = 5-7/6-8 ft, so a range and its bucket always agree.
- **2026-10-27 · Overhead (5-7 ft) is ok with a warning; 6-8 ft and up is a no-go.** The limit is "beyond 7 ft"; Surfline's 6-8 ft range means sets past 7 ft, so the no-go starts at that range (our 6.5 ft boundary) and a range never straddles go/no-go. The warning is `preferences.warn_sizes`, so other sizes can be flagged too.
- **2026-10-27 · One quick retry on 5xx from the APIs.** NOAA returned 502/504 for a few seconds while testing; a cache miss in that moment would show visitors the error page. Timeouts aren't retried, to stay inside the function's time limit.
- **2026-10-27 · Green/orange palette (mockup option C).** Dark green `#12873F` = favored, light green `#7EE08F` = okay to surf, orange `#FF7A1A` = big-wave warning only, after Surfline's green rating scale. Green text on white uses the darker `#0E652F` (white on `#12873F` is 4.6:1). Hover and selection outlines moved from orange to navy so orange always means a warning; the warning uses a drawn triangle icon instead of the ⚠ character.
